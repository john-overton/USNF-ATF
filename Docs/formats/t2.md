# T2: terrain / theater

Status: **partial** (header, grid dimensions, cell layout and land/sea mask
decoded; the meaning of the elevation and class bytes is inferred, not
measured). Reader: `tools/retail/retail/t2.py`.

    PYTHONPATH=tools/retail python3 -m retail.t2 --list extracted/usnf97/USNF_2.LIB
    PYTHONPATH=tools/retail python3 -m retail.t2 extracted/usnf97/USNF_2.LIB/KURILE.T2   # ASCII map

## Theaters

| file | name | tiles | cells | size | land |
|---|---|---|---|---|---|
| USNF'97 `KURILE.T2` | Kuril Islands | 32 x 32 | 256 x 256 | 199,829 | 5% |
| USNF'97 `UKR.T2`, `~UKR1..8.T2` | Ukraine | 26 x 25 | 208 x 200 | 126,899 | 77% |
| USNF'97 `VIET.T2` | North Vietnam | 25 x 25 | 200 x 200 | 122,024 | 59% |
| ATF Gold `BAL.T2` | The Baltics | 32 x 32 | 256 x 256 | 199,829 | see below |
| ATF Gold `EGY.T2` | Egypt | 26 x 25 | 208 x 200 | 126,899 | 72% |
| ATF Gold `FRA.T2` | France | 26 x 25 | 208 x 200 | 126,899 | 93% |
| ATF Gold `VLA.T2` | Vladivostok | 26 x 25 | 208 x 200 | 126,899 | 64% |

The eight `~UKRn.T2` files are byte-identical to `UKR.T2`; the campaign
missions that reference them differ only in their `.M` and `.LAY` content.
ATF Gold missions also reference `$bal2.t2`, `$vla4.t2` and so on; those
files are not on the disc, so the `$`/`~` prefix plus digit is a campaign
variant name that resolves to the base terrain, exactly as in USNF'97.

## Layout

Little-endian. Every retail file satisfies
`size == 0x94 + cols*rows*3 + width*height*3 + 1`.

| offset | size | field |
|---|---|---|
| 0x00 | 4 | magic `BIT2` |
| 0x04 | 80 | display name, NUL padded |
| 0x54 | 16 | briefing-map `.PIC` name |
| 0x64 | u32 | 25 or 32 (tiles; equals 0x6c) |
| 0x68 | u32 | 0 |
| 0x6c | u32 | 25 or 32 |
| 0x70, 0x74 | u32 | 0 |
| 0x78 | u32 | 2048 = 8 << 8: cells per tile edge, 24.8 fixed point |
| 0x7c | u32 | width in tiles << 8 (Ukraine 26, which 0x64 does not show) |
| 0x80 | u32 | height in tiles << 8 |
| 0x84 | 16 | unknown |
| 0x94 | cols x rows x 3 | cell grid, row-major, x fastest, 3 bytes per cell |
| then | width x height x 3 | tile table, 3 bytes per tile (not yet interpreted) |
| then | 1 | trailing byte |

`cols = width * 8`, `rows = height * 8`. The row stride of the cell grid was
confirmed by the periodicity of the sea pattern (768 bytes in Kuril, 624 in
Ukraine, 600 in Vietnam) and by rendering the grid: the Kuril arc runs
top-left to bottom-right, North Vietnam's coast is on the right with the
Gulf of Tonkin as sea, Ukraine has the Black Sea along the bottom-right.

## Cell bytes

| byte | observed | reading |
|---|---|---|
| 0 | 0 at sea, 0..24 on land, higher in mountains | elevation class (unit unknown; not raw feet) |
| 1 | 0xFF at sea; 0xC2..0xD9 on land, one dominant value per theater | texture / tile-set id |
| 2 | 0..12 | land-class code; sea is usually 1, coast 0 |

Open sea is `(0, 0xFF, 1)`; `(0, 0xFF, 0)` occurs along coasts. The reader
treats texture 0xFF as water. **The Baltics is the exception**: 70% of its
cells are `(0, 0xD2, 0)` and only 10% carry 0xFF, so either the Baltic Sea
uses its own texture id or the water test needs the tile table. Unresolved.

## World coordinates

Mission `pos x y z` (see [mission.md](mission.md)) maps to the cell grid as
`col = x // 8192`, `row = z // 8192`, y up. Calibrated by placing the 1,557
static `.OT` objects of all USNF'97 missions on their terrain: 99.5% fall on
land cells at this scale with no axis swap or flip; every other power of two,
swap or flip scores far worse. Altitudes in missions and in `.PT` are feet,
so a cell is 8,192 ft (2.5 km), a tile 65,536 ft (20 km), and the theaters
are 640 x 640 km (Kuril, Baltics), 520 x 500 km (Ukraine, Egypt, France,
Vladivostok) and 500 x 500 km (Vietnam).

## What is not in the file

There is no height field in the sense of a DEM: 3 bytes per 2.5 km cell.
Elevation must come from the phase 2 pipeline (real DEM data); the `.T2`
gives the theater extent, the coastline at 2.5 km, and the land classes for
tinting. The tile table (3 bytes per 20 km tile) and the 16 unknown header
bytes are the remaining work.
